# RISC-V 多磁盘与 D1 块设备接口说明

日期：2026-10-06。接口版本：D1 v1。比较基线：官方 xv6-riscv-rev5。

负责范围：C 成员的 HAL、块设备与多磁盘模块。本阶段实现 RISC-V 平台的三磁盘管理和 D1 接口，供后续文件系统后端接入。VFS、ext2/FAT32 及 LoongArch 的集成进度另行验收。

构建修复：补齐 Makefile 所需的 mkfs/mkfs.c，并将 .gitignore 中的 mkfs 规则调整为仅忽略生成程序 mkfs/mkfs。

## 已实现

- RISC-V QEMU virt 前三处 VirtIO MMIO 插槽，分别对应逻辑设备 1、2、3。
- 每台设备独立队列、完成状态、自旋锁及请求睡眠锁；按设备分发中断。
- 原生 ROOTDEV=1、BSIZE=1024、bread/bwrite 与日志调用方式保持兼容。
- blk_read、blk_write、blk_size、blk_flush；字节偏移、同步完成、0/-1 返回值。
- 非对齐请求通过 512 字节扇区适配；范围睡眠锁覆盖完整读改写，避免相邻区域的并发写互相覆盖。
- 容量、设备号、零长度、空缓冲和偏移溢出检查；设备错误返回失败。
- 协商只读、FLUSH 及现代 VirtIO VERSION_1 特性。FLUSH 发送真实设备请求；不支持时返回 -1。
- blk_write 对非零长度的原生根盘原始写入返回 -1，防止绕过缓存和日志。

## 接口使用

先包含 kernel/types.h，再包含 kernel/blkdev.h。

```c
int blk_read(uint dev, uint64 byte_off, void *dst, uint nbytes);
int blk_write(uint dev, uint64 byte_off, const void *src, uint nbytes);
int blk_size(uint dev, uint64 *out_bytes);
int blk_flush(uint dev);
```

只接受有效内核缓冲，不直接接受用户指针。可能睡眠，不能在中断中或持自旋锁时调用。
读取返回 0 才能使用整段数据；失败时缓冲可能已有部分内容。写入失败可能已修改前面的扇区，不承诺回滚。
正常写回时，文件系统先提交自身脏状态，再调用 blk_flush；设备 flush 不替代文件系统缓存写回。
同一可写设备只归一个文件系统实例。新增后端使用 D1；原生根盘保留缓存/日志入口。
blk_read 对根盘仅适合受控诊断；它不提供与原生脏缓存的自动一致性。

## 设备映射

| dev | QEMU bus | MMIO | IRQ | 用途 |
|---|---|---|---|---|
| 1 | virtio-mmio-bus.0 | 0x10001000 | 1 | fs.img，原生根盘 |
| 2 | virtio-mmio-bus.1 | 0x10002000 | 2 | 计划用于 ext2 裸卷；当前验证使用测试盘 |
| 3 | virtio-mmio-bus.2 | 0x10003000 | 3 | 计划用于 FAT32 裸卷；当前验证使用测试盘 |

编号来自上述固定插槽，不依赖 -drive 参数的排列顺序。初版不扫描任意总线，不支持热插拔或运行时扩容。
数据卷以字节 0 为卷起点。驱动本身不解析分区表，后端必须检查格式，不能将带分区表的磁盘误认作裸卷。

## 对公共文件的改动

- kernel/vm.c：扩大 VirtIO MMIO 的映射范围。
- kernel/plic.c：启用三台设备的中断。
- kernel/trap.c：按 IRQ 分发到设备。
- Makefile：增加 blkdev 对象、可选 DISK2/DISK3 参数、诊断构建选项。
- .gitignore：只忽略 mkfs 程序，并排除 test-output。

公共文件涉及平台初始化、地址映射、中断分发和构建配置，由 A 协调审阅；B 接入后端时核对 D1 声明及设备映射。

## 复现

在 Ubuntu 的 xv6-riscv 目录中执行；QEMU 已加入 PATH 时可省略环境变量设置：

```bash
export XV6_QEMU=/实际安装路径/qemu-system-riscv64
python3 tests/run_c_tests.py --quick
```

每次新建 test-output/run-*，保留旧证据。去掉 --quick 将执行完整 usertests，耗时更长。
脚本为诊断内核、普通内核、只读测试及重启读回分别建立构建副本，避免混用编译宏或删除有效镜像。

后端联调时，通过 DISK2/DISK3 连接相应的文件系统镜像；文件访问需要后端完成接入：

```bash
make qemu QEMU=/绝对路径/qemu-system-riscv64 DISK2=/绝对路径/ext2.img DISK3=/绝对路径/fat32.img
```

普通构建默认不链接 blkdev_test.o。BLKDEV_SELFTEST=1 仅用于脚本生成的一次性数据盘；该测试会修改数据盘，不能对真实文件系统镜像启用。
