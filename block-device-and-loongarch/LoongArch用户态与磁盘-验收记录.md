# LoongArch 用户态与 PCI 磁盘阶段验收

日期：2026-10-21。状态：实现与验证完成，已获准提交到 hal-platform 分支；未合并主线。

## 本轮做了什么

1. PLV3 用户态程序、独立用户栈、可信内核陷阱栈、最小系统调用和返回。
2. 两个正常程序的主动让出和定时器抢占，以及七个地址空间的运行与回收；五个越权程序被分别隔离。
3. 跨页用户复制、权限与溢出检查；拒绝非法缓冲区、只读 copyout 和未知系统调用。
4. LoongArch PCI VirtIO Modern/Legacy 磁盘及 D1 字节接口，独立队列、bounce buffer、部分扇区读改写、容量、只读和根盘保护、FLUSH 与设备错误返回。
5. 用户态程序通过系统调用实际读写 PCI 磁盘，刷新后读回，宿主确认修改范围。
6. 统一自动化回归及可交互展示的 demo_platform.py，每次只使用新建的一次性镜像。

本轮是在已有基础模块上完成独立闭环，未修改 xv6-riscv，未引入队友的文件系统实现。

## 实际验证

最终运行：`run-20261021-212549`。29 个自动化检查项均通过（包括宿主 sanitizer、目标程序和镜像核对，不能理解为 29 个 xv6 usertests）。

| 无设备、单根盘和宿主未修改核对 | 通过 |
| Modern 三盘、同镜像重启、宿主逐字节核对 | 通过 |

所有新增目标使用 `-Wall -Wextra -Werror` 编译。没有重跑 RISC-V usertests，因为本轮没有修改该目录或构建入口。此前 RISC-V 回归记录保留，不代表三方集成后的结果。

最终证据位于 `证据/20261021/LoongArch-runtime-and-pci/`，含构建、串口、异常、设备错误配置、ELF 布局和 manifest。manifest 记录源码、Makefile、脚本、QEMU 二进制及镜像前后/期望 SHA256。自动化输入镜像可按脚本重建，不放入提交包。

## 复现与展示

详见 [机制与复现说明](LoongArch用户态与磁盘-说明与复现.md)。在 Ubuntu/WSL 配置 LOONGARCH_CROSS 和 LOONGARCH_QEMU 后，进入 loongarch-probe：

```sh
python3 run_probes.py
python3 demo_platform.py
```

演示显示两个用户态程序的系统调用输出、预期的隔离异常、抢占计数和磁盘闭环；看到 `user: ALL PASS` 后按 Ctrl+A 再按 X 退出。

## 还没有完成的内容

这不是完整 LoongArch xv6。正式 proc/fork/exec/wait、整机 RAM 发现、正式内核并发块设备、VFS 与 ext2/FAT32、shell 和整体验收仍需接入主线。现有进程调度和磁盘实现是单 CPU 独立验证框架；不支持多核、浮点/向量上下文、任意 PCI 拓扑或热插拔。

下一步需要组长确定集成基线、架构目录、异常帧/内核栈、内存与进程接口，再将已经验证的机制接入主线；不需要等队友把所有功能做完，但不能未经约定覆盖公共内核文件。此前集成版本的偶发异常仍待排查。

本轮已获用户批准，提交到 hal-platform 分支，供团队审阅与后续集成；不合并 master。
