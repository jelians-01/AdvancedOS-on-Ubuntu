# LoongArch 平台适配与主线接入计划

本地独立验证已推进到用户态、最小系统调用、抢占调度、PCI VirtIO D1 和用户态到磁盘链路；本轮已获准提交到 hal-platform 分支。完整 LoongArch xv6 和最终文件系统成品尚未完成。机制与复现见 [用户态与磁盘说明](LoongArch用户态与磁盘-说明与复现.md)。

## 已有独立验证

| 内容 | 验证范围 |
|---|---|
| 启动、串口、异常与上下文 | QEMU 加载、异常现场、ertn、定时器和独立栈 |
| 物理内存与分页 | 预留 1 MiB，4 KiB 基本页、16 KiB 叶子、软件 TLB 重填及权限 |
| 用户态与复制 | PLV3、可信内核异常栈、跨页 copyin/out、权限与溢出拒绝 |
| 调度与进程隔离 | 两个正常程序、五个故意越权程序；抢占、让出、退出与资源回收 |
| PCI VirtIO 与 D1 | Modern、Legacy、混合三盘、单根盘、无设备、只读和非对齐读改写 |
| 持久化与错误 | FLUSH 后同镜像重启读回、宿主精确字节核对、blkdebug 读错误及重试 |
| 跨层链路 | PLV3 系统调用到 D1，再到 PCI 磁盘；Modern 和 Legacy 均通过 |

## 接下来需要对齐的事项

接下来应将已验证机制接入正式内核，不能把独立实验通过当作主线已经集成通过。

| 事项 | 需要确定的接口或完成标准 |
|---|---|
| 集成基线 | 确定包含 VFS、文件系统后端和 D1 的主线测试基线 |
| 架构目录与构建 | 选择 LoongArch 对象，避免与 RISC-V 同名符号同时链接 |
| 异常帧和内核栈 | 对齐寄存器布局、CSR 暂存用途、每进程内核栈及返回约定 |
| 正式进程管理 | 接入主线生命周期、fork/exec/wait、文件描述符和 cwd |
| 正式内存管理 | 确定 RAM 发现、保留区和耗尽策略；当前不是整机内存管理 |
| 块设备并发 | 明确 polling 原型如何接入正式内核的锁、休眠和完成通知 |
| 文件系统与 shell | 经 VFS 访问数据盘文件，启动真实用户程序和 shell，做完整回归 |
| 已知集成异常 | 继续排查此前偶发内核异常，独立验证不替代根因分析 |

## 环境与边界

- 已验证交叉编译器为 GCC 13.0.0，QEMU virt 单 CPU、2 GiB；PNX 测试使用独立回移官方修复的 QEMU。
- PCI 地址依据本机 QEMU 7.2 平台源码，尚未验证真实板卡和任意 PCI 拓扑。
- 浮点/向量现场、多核、嵌套内核中断、热插拔均未包含。
- 没有替换公共 proc.c、exec.c、syscall.c、defs.h 或主线 Makefile。正式接入前先和对应维护者对齐接口，并保留 RISC-V 回归入口。
